7.额外内容2--XZ 事件

一个差点掀翻全球 Linux 的后门：XZ 事件 你可以先想象一个画面：整个互联网像一座巨大的城市，水、电、交通都靠无数管道和线路撑着。但很多关键管道，不是大公司维护的，而是某个不知名的程序员，用业余时间默默修了十几年。
XZ Utils 就是这样一个工具。它是一个压缩软件，几乎运行在所有 Linux 系统上，包括 systemd 和 OpenSSH 等关键组件在不知不觉中依赖了它。芬兰程序员 Lasse Collin 从 2005 年起几乎一个人维护 XZ，接近二十年，长期没有报酬。2022 年，他公开表示自己正遭受长期心理健康问题的困扰。而一场疑似由国家级情报机构主导的行动，在此前数月便已悄然展开。
就在这时，一个叫 Jia Tan 的用户出现了。他很热心，持续帮忙改代码、分担工作，慢慢赢得信任，最后顺利接手了维护权。但 Jia Tan 不是普通开发者，而是一个精心伪装的化名。他真正的目标，是把 XZ 当成跳板，潜入 OpenSSH 的依赖链，在 SSH 登录认证环节埋后门。
他的计划大概分三步。 第一步，藏毒。 他把恶意代码藏在 XZ 的测试文件里，伪装成损坏的压缩测试用例，然后在编译脚本中加入解包代码，让恶意逻辑在构建时悄悄释放出来。这些恶意代码只存在于发布压缩包中，而在 Git 仓库里根本看不到，从而绕过了常规的源码审查。
第二步，偷梁换柱，并留一把只有自己人能打开的锁。 Jia Tan 利用 Linux 的 IFUNC（间接函数）解析机制，在程序初始化阶段——此时全局偏移表（GOT）和过程链接表（PLT）尚未被标记为只读——悄悄把 OpenSSH 用于验证 RSA 密钥的函数 RSA_public_decrypt 替换成了自己的恶意实现。通俗点说，就像锁匠正在检查钥匙的那一刻，有人把锁匠换成了自己人。
替换之后，这个假锁匠怎么知道站在门外的是普通用户还是自己人呢？答案是：只有持有特定 Ed448 私钥的攻击者才能触发后门。 正常 SSH 公钥认证的流程是：客户端用私钥对一段数据签名，服务端用客户端提供的公钥验证签名。而 OpenSSH 证书有一个特殊设计——证书里包含了签发者的公钥。攻击者可以在发起连接时，构造一张特制的 SSH 证书，把指令内容伪装成“公钥”塞进去。后门版的 RSA_public_decrypt 拿到这个公钥后，先检查里面是否藏有符合特定格式的载荷，再用一个硬编码在后门代码里的 Ed448 公钥去验证载荷上附带的 Ed448 签名。
只有用对应的 Ed448 私钥签出来的名，才能通过这个验证。验证通过后，后门从载荷中解出攻击者预先写入的命令，直接调用 system() 以 root 权限执行，整个过程发生在 SSH 认证阶段，攻击者甚至不需要知道任何合法的用户名和密码，就能在认证完成之前拿到系统的最高权限。更隐蔽的是，如果签名验证失败或载荷格式不对，后门会回退到正常的 RSA_public_decrypt 行为，让一切看起来毫无异常。
第三步，擦痕迹。 这个后门不是随便就触发，只有收到特定主密钥才会启动，而且还会抹掉登录日志，让入侵看起来像什么都没发生。

 

 

本来这可能成为一次极其严重的供应链攻击。但它被一个偶然发现拦住了。
2024 年 3 月下旬，微软工程师 Andres Freund 在 Debian sid 系统上运行 PostgreSQL 的性能微基准测试时，注意到 SSH 连接不仅慢了大约 500 毫秒，而且 SSH 守护进程消耗的 CPU 时间异常高。500 毫秒，很多人可能根本不会在意。但他没有忽略，而是开始对 SSH 守护进程进行性能分析，发现它在认证阶段竟然在调用 liblzma 压缩库——这在正常情况下绝不应该发生。他顺藤摸瓜，最终在 2024 年 3 月 29 日向 oss-security 邮件列表披露了这个后门。
这时，恶意版本已经进入 Fedora 41 和 Rawhide、Debian 测试版、openSUSE Tumbleweed、Kali Linux 和 Arch Linux 的安装介质。CVE-2024-3094 被赋予 CVSS 10.0 的最高严重性评分，因为成功利用它可以完全远程接管受影响系统，且无需任何权限。如果没被发现，后果不堪设想。
那 Jia Tan 到底是谁？到今天也没有公开确证。但很多线索让人怀疑，这不是个人恶作剧，而是有组织、有资源、有耐心的长期情报行动。调查记者 Brian Krebs 证实，从 2022 年 4 月开始出现在邮件列表中的几个“施压”账号，在互联网上没有任何其他踪迹，在大型数据泄露库中也找不到记录，这在现实中几乎不可能。而对 Jia Tan 的 Git 提交时间戳分析显示，他的工作时间有几次从 UTC+08 切换到 UTC+02 和 UTC+03，且在中国节假日期间提交代码，在东欧节假日却没有提交。这些线索都指向有组织的长期情报行动。
事后，开源社区进行了大量排查，但所有人都明白：这次是运气好。Tidelift 2025 年开源维护者报告显示，60% 的维护者是无偿爱好者，44% 在过去一年考虑过退出，22% 的关键项目只有一名活跃维护者。在 XZ 事件后，OpenSSF Alpha-Omega 项目的研究人员又识别出超过 50 个具有类似结构性暴露的关键项目。
这起事件真正暴露的，不只是一个代码漏洞，而是整个开源生态的系统性脆弱：全球数字基础设施，常常依赖无偿维护的个人；而安全，有时只靠某个开发者偶然注意到“慢了 500 毫秒”。XZ 事件不是例外，而是预警。下一次，未必还有人正好看见那半秒异常。
